GitHubMenu - Guide utilisateur

Guide d'utilisation de l'interface graphique GitHubMenu pour piloter GitHub CLI sans retenir les commandes par cœur.

GitHub CLIReleasesWorkflows

Objectif

GitHubMenu aide à effectuer les opérations GitHub les plus utiles depuis une fenêtre unique : vérifier l'état d'un dépôt, publier une version, télécharger une release, consulter l'historique et ouvrir le dépôt dans le navigateur.

Démarrage

  1. Ouvrir GitHubMenu.
  2. Sélectionner le dépôt local à traiter.
  3. Choisir une action dans le menu de gauche.
  4. Lire le résultat affiché dans la zone principale.

Menu principal

État GitHub

Affiche l'authentification GitHub, le dépôt courant et les informations principales renvoyées par GitHub CLI.

Publier une nouvelle version

Prépare la création d'une release GitHub pour le dépôt sélectionné, avec les fichiers et informations de version associés.

Historique et téléchargement

Permet de consulter les releases existantes et de récupérer les fichiers publiés pour une version.

Workflows

Affiche les workflows GitHub Actions et leurs dernières exécutions afin de suivre les automatisations du dépôt.

Exemples d'utilisation

Vérifier qu'un dépôt est prêt avant publication

Action conseillée : État GitHub

Sélectionner le dossier du projet, puis ouvrir l'état GitHub. L'outil confirme l'authentification, le dépôt distant associé et les informations renvoyées par GitHub CLI. C'est le premier contrôle à faire avant de créer une release ou de consulter les workflows.

Si le dépôt n'est pas reconnu, vérifier que le dossier contient bien un dépôt Git et qu'un remote GitHub est configuré.

Publier une version de l'application

Action conseillée : Publier une nouvelle version

Après avoir sélectionné le dépôt, renseigner le numéro de version, le titre de la release et les fichiers à joindre, par exemple un exécutable généré dans dist. GitHubMenu prépare l'appel à GitHub CLI et affiche le résultat dans la zone principale.

Utiliser un numéro de version cohérent, par exemple v1.2.0, pour faciliter le suivi des publications et éviter les doublons.

Télécharger un fichier publié dans une ancienne release

Action conseillée : Historique et téléchargement

Ouvrir l'historique pour lister les releases disponibles, choisir la version voulue, puis télécharger l'asset associé. Cette opération est utile pour récupérer rapidement une version stable, comparer deux livraisons ou transmettre un fichier déjà publié.

Si aucun fichier n'apparaît, la release existe peut-être sans asset joint : consulter alors la page GitHub de la release pour confirmer son contenu.

Suivre une automatisation GitHub Actions

Action conseillée : Workflows

Afficher les workflows pour voir les automatisations du dépôt et leurs dernières exécutions. Cela permet de repérer rapidement une compilation réussie, un test en erreur ou une publication automatisée encore en cours.

En cas d'échec, ouvrir le workflow concerné dans GitHub pour lire les logs détaillés et identifier l'étape bloquante.

Versions

Les actions liées aux releases reposent sur le dépôt GitHub associé au dossier local. GitHubMenu s'appuie sur les droits de l'utilisateur authentifié avec GitHub CLI.

Dépannage

  • Si l'authentification manque, relancer la connexion GitHub CLI.
  • Si le dépôt n'est pas reconnu, vérifier que le dossier choisi est bien un dépôt Git.
  • Si une release existe déjà, choisir un autre numéro de version ou consulter l'historique.
  • Si une commande échoue, lire le diagnostic affiché dans la zone de résultat.
